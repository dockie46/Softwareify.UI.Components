## Findings

### FND-1: CSS variable tokens resolve to black — theme broken out of the box

- **Type**: Bug
- **Severity**: Critical
- **Related FR**: FR-3
- **Routing**: Revision
- **Description**:
  `designTokens.ts` sets antd theme tokens to CSS custom properties (e.g.
  `colorBgContainer: 'var(--color-bg-primary)'`, `colorBorder: 'var(--color-border)'`).
  These CSS variables are never defined — not in Storybook, not in the library's CSS output,
  and not in the consumer's environment by default.

  **Expected**: Theme works out of the box with sensible defaults. CSS variables serve as
  optional overrides.

  **Actual**: Table headers render solid black, input/checkbox borders are invisible,
  empty table backgrounds are off-color. The theme is fundamentally broken on first use.

  **Root cause**: `softwareifyTheme.token.colorBgContainer` = `'var(--color-bg-primary)'`
  which is an unresolved CSS variable string passed to antd's JS-based token system.

  **OCPP Server reference**: Uses concrete hex values (`colorBorder: '#E7EAF0'`), no CSS variables.

### FND-2: i18n keys show raw `global.btns.*` strings in buttons

- **Type**: Bug
- **Severity**: Critical
- **Related FR**: FR-5
- **Routing**: Revision
- **Description**:
  Components use `t("global.btns.cancelChanges")` but the translation file `en.json` has
  keys at root level (`btns.cancelChanges`), and the namespace is `softwareify-ui`.
  The resolved key `softwareify-ui:global.btns.cancelChanges` doesn't exist.

  **Expected**: Button labels show translated text ("Cancel Changes", "Save Changes",
  "Cancel", "Confirm", "Copy", "Copied!", "Clear", "OK", "Reset", "Primary Key").

  **Actual**: Raw i18n keys displayed as button text (e.g. `global.btns.cancelChanges`).

  **Affected files** (6 files, 10 occurrences):
  - `BaseModal.tsx` (2): `global.btns.cancelChanges`, `global.btns.saveChanges`
  - `ConfirmModal.tsx` (2): `global.btns.cancel`, `global.btns.confirm`
  - `PrimaryKey.tsx` (3): `global.labels.primaryKey`, `global.btns.copy`, `global.btns.copied`
  - `SignatureCanvas.tsx` (2): `global.btns.clear`, `global.btns.confirm`
  - `columnFilters.tsx` (2): `global.btns.ok`, `global.btns.reset`

### FND-3: Form story decorators use horizontal layout instead of vertical

- **Type**: Bug
- **Severity**: Major
- **Related FR**: FR-7
- **Routing**: Revision
- **Description**:
  All 10 form input story files use `<Form>` without `layout="vertical"` as the decorator.
  Antd defaults to `layout="horizontal"`, placing labels beside inputs.

  **Expected**: Labels appear above inputs (vertical layout), matching the OCPP Server's
  form pattern (`<Form layout="vertical">`).

  **Actual**: Labels appear beside inputs (horizontal layout). The checkbox story shows
  only text with no visible checkbox control to its left.

  **Affected files** (10 stories):
  `InputFormItem`, `CheckboxFormItem`, `SelectFormItem`, `SwitchFormItem`,
  `NumberFormItem`, `DateFormItem`, `TimePickerFormItem`, `TextAreaFormItem`,
  `FormItemWrapper`, `FormSection` — all `.stories.tsx` files.

  **Note**: `BaseModal.stories.tsx` already uses `layout="vertical"` correctly.

### FND-4: Checkbox border invisible due to unresolved `colorBorder` token

- **Type**: Bug
- **Severity**: Major
- **Related FR**: FR-3
- **Routing**: Revision (auto-fixed by FND-1)
- **Description**:
  The antd Checkbox component renders without a visible border/box. The checkbox control
  exists in the DOM but its border color resolves to transparent/invisible.

  **Root cause**: Same as FND-1 — `colorBorder: 'var(--color-border)'` is unresolved.
  Fixing FND-1 by providing concrete fallback values will automatically fix this.

  **No separate fix needed** — this finding is tracked for completeness.

### FND-5: `borderRadius` mismatch with OCPP Server (6 vs 4)

- **Type**: Improvement
- **Severity**: Minor
- **Related FR**: FR-3
- **Routing**: Revision
- **Description**:
  The UI Components library sets `borderRadius: radius.md` = `6` in `softwareifyTheme`.
  The OCPP Server uses `borderRadius: 4`.

  **Expected**: Visual consistency between the library and its primary consumer.
  **Actual**: Components have slightly rounder corners than the OCPP app expects.
